# Граф денег — frontend (план C)

React 19 + TypeScript + Vite 7 + Cytoscape.js. Реализация ограничена `frontend/`; архитектура, Python-код, правила анализа и контракт не изменены.

[План реализации](docs/implementation.md) · [Фактические проверки и скриншот](docs/verification.md)

## Запуск с backend B

Требуется Node.js 22.12+ (проверено на 24.18.1) и npm. Из этого каталога:

```sh
npm ci
npm run dev
```

Открыть <http://127.0.0.1:5173>. Vite проксирует `/api` в `http://127.0.0.1:8000`. Другой адрес задаётся в `frontend/.env.local`:

```dotenv
API_PROXY_TARGET=http://127.0.0.1:8000
```

Backend должен отдавать один завершённый запуск по [контракту 1.0](../docs/contracts/money-graph-v1.md). Без него интерфейс показывает состояние ошибки и повтор запроса. AI-ключи в браузере не используются.

Происхождение данных определяется при загрузке и обновлении набора по заголовку `X-Data-Source` ответа `/api/health`: `fixtures` включает предупреждение об искусственных данных, `artifacts` отключает его. Один и тот же собранный `dist` подходит для обоих режимов backend, в том числе в Docker. JSON-контракт не меняется. Если заголовок отсутствует, сохраняется локальный fallback `VITE_DATA_SOURCE=fixture`, используемый `npm run dev:fixtures`.

## Проверка без backend

Отдельный сервер внутри `tests/` отдаёт исключительно искусственные ответы для проверки интерфейса. Он не входит в сборку и не является заменой backend или аналитики. В двух терминалах:

```sh
npm run fixtures
```

```sh
npm run dev:fixtures
```

Открыть <http://127.0.0.1:5174>. Баннер обозначает искусственные данные. Проверить `0007`, `0042` (граница наблюдения), `0999` (изолированный), неизвестный gid. Через вкладку кластеров доступна искусственная компонента `fixture-large` с ограничением 300 из 320 узлов. Роли и баллы фикстур — заданные тестовые значения, а не утверждённые аналитические правила.

## Сборка и проверки

```sh
npm test
npm run build
```

`npm test` проверяет гонку A/B с поздним ответом, смену run_id карточки и графа, 404, gid с ведущими нулями, null/0, точность денежных строк, сброс AI при смене объекта/запуска, 409, повтор вопроса и fallback. Также проверяется баннер искусственных данных по заголовку backend, его обновление и совместимость с локальным fixture-сервером без заголовка. Native config loader избегает лишней сборки конфигурации тестов.

Статика создаётся в `frontend/dist`. B может обслуживать этот каталог вместе с `/api` на одном origin. JS, CSS, иконки и Cytoscape включены в сборку, внешние CDN и шрифтовые запросы не требуются. `npm run preview` подходит для просмотра статики; API под ним отдельно не проксируется.

## Реализованные сценарии

- Точный поиск строкового gid по Enter/кнопке, выбор из топ-20 и графа.
- Направленный граф, легенда шести ролей, радиус 1/2, кластер и компонента, масштабирование, клавиатурный выбор узла.
- Объяснения роли и приоритета, таблицы условий, раздельные баллы, точные денежные строки в подсказках, качество и ограничения наблюдения.
- Ограничение выдачи графа с количеством показанных узлов. Метрики из NodeRecord не пересчитываются по видимому графу.
- Оба AI-режима через backend, вопрос, отмена, повтор, основания, проверки, ограничения и явно отмеченный fallback.
- Отмена и поколения запросов исключают подмену текущей карточки поздним ответом. Несовместимый run_id сбрасывает карточку/граф/AI и загружает свежий набор.
- Скачивание восьми обязательных артефактов с проверкой текущего run_id до/после загрузки.
- Адаптивная компоновка, прокрутка длинной карточки, видимый фокус и reduced motion.

## Передача участнику B

1. Сверить `src/types/api.ts` со снимком `contracts/openapi.json`, когда он появится. Сейчас типы выведены из письменного контракта v1.
2. Предоставить общие фикстуры B, настоящий набор A и проверить три реальных примера через поиск, топ и граф. Локальный тестовый сервер этого не подтверждает.
3. Подтвердить логические ключи `manifest.files`: `nodes`, `edges`, `clusters`, `priorities`, `roles`, `rules`, `audit`, `manifest`. Они используются в `/api/exports/{name}`. Контракт задаёт разрешённые имена через manifest, но не фиксирует значения этих ключей; при других ключах обновить соответствие в `ExportMenu.tsx`.
4. При проксировании `/api/health` сохранять заголовок `X-Data-Source`, чтобы frontend автоматически обозначал искусственные данные. Отдельный флаг сборки для fixture-режима backend не требуется.
5. Обслуживать `dist` и проверить скачивание файлов через настоящий FastAPI. Реальные данные, внешние AI-провайдеры, производительность аналитики и общий end-to-end от parquet не проверены этой frontend-работой.

Приоритет — порядок проверки, соответствие роли — мера формальных правил. Ни одно значение не трактуется как вероятность виновности. Полнота наблюдения `null` остаётся неизвестной; отсутствие наблюдаемых исходящих не превращается в доказанное отсутствие переводов.

Решения по внешним библиотекам сверялись с [Vite](https://vite.dev/guide/), [Cytoscape.js](https://js.cytoscape.org/) и [React](https://react.dev/reference/react/useEffect).
