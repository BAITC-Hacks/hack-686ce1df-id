# AI: пояснение и ограниченное исследование

AI интегрирован с FastAPI, настоящим ResultStore и интерфейсом. Пользователь
23.09.2026 подтвердил, что объяснения работают через его API-ключи. Это
подтверждение эксплуатации; отдельный протокол с моделью, задержкой и проверкой
всех функций живого провайдера не записывался. Автоматические тесты используют
имитацию сети и не расходуют API-кредиты.

Основные роли, приоритеты, гипотезы кластеров и CSV вычисляются локально без AI.
При отсутствии или недоступности провайдера приложение сохраняет эти результаты
и показывает локальные объяснения с явной пометкой fallback. Проверки полного
расчёта и интерфейса описаны в [отчёте реального запуска](real-data-verification.md).

## Что работает

- `AIService.explain(request, store)` — один запрос провайдеру, без функций.
- `AIService.investigate(request, store)` — четыре разрешённых имени функций,
  максимум три исполнения суммарно, включая пакеты из нескольких вызовов.
- Без ключа, модели, зависимости `httpx`, при отказе, неправильном ответе,
  неизвестной функции или исчерпании времени возвращается локальная справка.
  Её `status="fallback"`, причина — безопасный код `fallback_reason`.
- Локальные объяснения роли/приоритета, гипотеза кластера и ограничения качества
  доступны независимо от OpenAI. Роли, score и правила не изменяются.
- Завершённые проверки сохраняются в `checks`, даже если следующая проверка
  или обращение к модели не удались. Частичный результат не выдаётся за
  завершённое исследование. Четвёртый вызов в пакете не исполняется.
- Есть общий срок на чтение карточки, все обращения к провайдеру и Store.
  Отдельный новый тайм-аут на каждый шаг не продлевает общий срок.

Код выполняет чтение одного неизменяемого запуска. `run_id` проверяется до и после
чтений, после каждого ответа провайдера и перед возвратом результата. Смена запуска
возвращает ошибку для HTTP 409, а не справку с данными разных запусков.

## Подключение к backend

HTTP-маршруты уже подключены к публичным функциям:

```python
from backend.app.ai.service import explain, investigate

response = await explain(request, store)
response = await investigate(request, store)
```

Они принимают модели запроса и возвращают `backend.app.contracts.AIResponse`
через `AIResponse.model_validate(...)`. Нижележащий `AIService` возвращает словарь
той же формы; отдельной схемы HTTP для AI нет.

Store должен предоставлять:

```python
run_id: str  # текущий законченный неизменяемый запуск
get_node(gid: str) -> NodeRecord
get_neighbors(gid: str, radius: int = 1, limit: int = 50) -> GraphResponse
get_cluster(cluster_id: str) -> ClusterRecord
check_concentration(gid: str) -> dict
```

Синхронные методы выполняются в worker thread; поддерживаются и async-методы.
Store должен безопасно обслуживать параллельные чтения. Отмена ожидания не
останавливает уже выполняющийся синхронный метод: поэтому методы должны быть
короткими, читать память и не изменять результаты. При тайм-ауте их поздний
результат не попадает в ответ. Длительные вычисления относятся к пайплайну A.

Результаты могут быть Pydantic-моделями v2 или JSON-словарями. Неизвестный объект
обозначается `KeyError` либо исключением с `status_code=404`. Остальные ошибки
Store дают диагностируемый fallback. Перед соседями и концентрацией выполняется
проверка существования узла через `get_node`. Это служебная проверка ссылочной
целостности, не дополнительный выбор функции моделью. Первое чтение карточки
также не входит в бюджет трёх запросов модели к функциям.

HTTP-слой переводит `backend.app.ai.tools.RequestError` в общую форму APIError
с исходным кодом HTTP. Эквивалентный вариант обработки при другом подключении:

```python
from fastapi.responses import JSONResponse
from backend.app.ai.tools import RequestError

@app.exception_handler(RequestError)
async def ai_request_error_handler(request, exc):
    return JSONResponse(
        status_code=exc.status_code,
        content={"error": {"code": exc.code, "message": exc.message}, "run_id": exc.run_id},
    )
```

Некорректный запрос — 422; отсутствующая карточка — 404; нет готового запуска —
503; старый или изменившийся `run_id` — 409. Неизвестная функция или запрошенный
моделью отсутствующий ID дают fallback, сохраняя прежние завершённые проверки.
Полную валидацию артефактов и канонических моделей выполняет backend.

Общий проект требует Python **3.12+**. `httpx==0.28.1` включён в runtime-зависимости
для OpenAI, `pytest==8.4.2` — в тестовые. Эти версии проверены на Python 3.12.14.
OpenAI SDK и pytest-asyncio не требуются. Основной AI-сервис и локальная справка
работают на стандартной библиотеке, `httpx` импортируется только перед сетью.
Зависимости и транзитивные версии зафиксированы в общем `requirements.lock`.

## Конфигурация

Если корневого `.env` ещё нет, создать его по образцу `.env.example`. Если файл
есть, дополнить его, сохранив остальные настройки. Реальный ключ записывать
**только в `.env`**, исключённый из Git; `.env.example` остаётся шаблоном с пустым
ключом. В `.env` задать `OPENAI_API_KEY`, точный ID доступной в аккаунте модели
в `AI_MODEL` и `AI_PROVIDER=openai`. Не переносить ключ в Compose, Dockerfile,
frontend, примеры или команды терминала.

Основной Docker-запуск читает эти настройки и передаёт их серверу:

```sh
docker compose -f compose.yaml -f compose.real.yaml up --build --wait --wait-timeout 90
```

После изменения `.env` снова выполнить `up`, чтобы контейнер получил новое
окружение. Один `restart` переменные не обновляет. Для режима готовых артефактов
использовать `compose.artifacts.yaml` вместо `compose.real.yaml`. При запуске
Python без Docker корневой `.env` загружает конфигурация backend.

| Переменная | Значение и ограничение |
|---|---|
| `AI_PROVIDER` | `openai` по умолчанию; другой провайдер даёт fallback, переключения нет |
| `AI_MODEL` | Точное имя выбранной и проверенной в аккаунте модели; пусто по умолчанию |
| `OPENAI_API_KEY` | Только серверное окружение; не передавать в браузер и не хранить в Git |
| `AI_TIMEOUT_SECONDS` | По умолчанию `30`; конечное число `0 < timeout <= 30` |
| `AI_MAX_TOOL_CALLS` | По умолчанию `3`; целое от `0` до `3`; `0` отключает функции |

Сам AI-модуль `.env` не загружает; запуск FastAPI B читает корневой `.env`
через Settings, сохраняя приоритет существующего окружения. Некорректные
значения приводят к локальному fallback без вывода исходных значений переменных.
Ключ исключён из repr конфигурации. Ответы upstream, заголовки, вопрос и ключ
не включаются в сообщения ошибок и не печатаются модулем.

Используется только `https://api.openai.com/v1/responses`: `store=false`,
структурированный `text.format` с `strict=true`, разрешённые function tools.
Автоматических повторов нет. Провайдер получает только поля контракта, вопрос,
обязательные ограничения и основания, необходимые текущему диалогу. Переменные
HTTP proxy из окружения не используются (`trust_env=false`). Ни shell, ни файлы,
ни web search, ни изменение правил не доступны модели как функции.

`summary`, `claims`, `limitations` генерирует модель. Сервер самостоятельно
собирает полный AIResponse: `contract_version`, `run_id`, `status`, `checks` и
`fallback_reason` модель не задаёт. Зашифрованное состояние reasoning хранится
только в памяти текущего запроса для продолжения Responses; в `checks` и ответы
пользователю оно не включается. Контекст ограничен 128 000 байт JSON, вопрос —
4 000 символами. Превышение контекста даёт fallback, а не скрытую обрезку оснований.

После третьей успешной функции допускается один завершающий запрос модели с
отключёнными функциями и оставшимся временем. Если она опять просит функцию,
возвращаются локальная справка и сохранённые результаты с ограничением бюджета.

## Основания в интерфейсе

Схема идентификаторов без новых полей AIResponse согласована с пользователем.
ID стабилен в рамках карточки и её `run_id`; другой запуск — другое основание,
даже если текстовый ID совпадает. Компонент gid/cluster_id кодируется как URL
path segment (`encodeURIComponent` с обязательным percent-encoding знаков
`!'()*` для совместимости с Python `quote(..., safe='')`). Ведущие нули сохраняются.

| evidence_id | Исходный объект в интерфейсе |
|---|---|
| `node:0007:card` | текущий NodeRecord |
| `node:0007:metrics` | `node.metrics` |
| `node:0007:quality` | `node.quality` |
| `node:0007:role_explanation` | `{text: node.role_explanation}` |
| `node:0007:priority_explanation` | `{text: node.priority_explanation}` |
| `node:0007:role_evidence:0` | `node.role_evidence[0]` |
| `node:0007:priority_evidence:0` | `node.priority_evidence[0]` |
| `cluster:cluster-test:card` | текущий ClusterRecord |
| `cluster:cluster-test:hypothesis` | `cluster.hypothesis` |
| `check:1`, `check:2`, `check:3` | `checks.find(item => item.evidence_id === id).result` |

Элемент `checks` содержит имя реально выполненной функции, нормализованные
аргументы, точный результат Store и его evidence_id. Результат концентрации
берётся только из `store.check_concentration`, то есть из реализации A; формула
в AI не дублируется. Тестовый ответ 30 + 70 KZT → 0.7 явно искусственный.

Панель явно обозначает fallback и показывает `limitations`. При смене
карточки или запуска предыдущие AI-ответы сбрасываются. Граф с `truncated=true`
получает серверное пояснение о показанном и полном числе узлов.

## Достоверность: что проверяется

Сервер отклоняет дополнительные поля ответа, неправильные типы, несуществующие
основания, NaN/Infinity, пустые/слишком длинные строки и неверные числовые значения.
Числа допускаются только в claims с основаниями: модельные summary/limitations
пишутся без цифр. Каждое число сверяется только с процитированными объектами.
Идентификаторы, произвольный текст, boolean и null не считаются числовыми
основаниями. Денежные строки проверяются через Decimal; доля `0.7` допускает
`70%` только в полях share/ratio. Неоднозначная запись, округление без основания,
сокращения вроде «70 тыс.» и процентные пункты отклоняются.

Это консервативная проверка литералов, а не доказательство истинности речи.
Одинаковые числа в разных метриках одного основания, числа словами, причинность
и произвольные смысловые ошибки требуют проверки аналитиком. Узкий фильтр
категоричных заявлений о реальном конечном получателе не является полноценным
классификатором языка. Сервер всегда добавляет ограничения наблюдения; модель
не может убрать их из итогового ответа. Неполнота входящих, граница обхода,
неизвестная полнота и технический peripheral показываются отдельно.

## Проверки и примеры

Из корня проекта после установки `requirements.lock`:

```sh
.venv/bin/python -m pytest tests/ai -q
```

На Windows использовать `.venv\Scripts\python.exe`. Общие прогоны backend,
проверка OpenAPI и Docker указаны в [отчёте](real-data-verification.md).
Историческая проверка отдельного AI-модуля дала 94 прошедших теста; это число
раннего этапа разработки, а не полный объём текущего набора.

Проверяются сбои и отсутствие ключа, полный тайм-аут, ошибочные функции и аргументы,
пакеты вызовов, подмена ID/запуска, точные числа и ссылки, ноль/null, ограничения
обхода, неизменность Store, строгий Responses-запрос и продолжение после функции.
Все сетевые ответы в основном наборе имитируются через `httpx.MockTransport`;
API-кредиты не расходуются. Данные `tests/ai/fixtures.py` — только искусственные.

Примеры ответов лежат в `tests/ai/examples/success.json` и
`tests/ai/examples/fallback.json`; оба получены из того же искусственного Store.

## Необязательная отдельная проверка провайдера

Пользователь уже подтвердил работу AI в приложении. Для записи отдельного
протокола на новом аккаунте или другой модели можно явно запустить следующие
проверки в контейнере с настроенным `.env`. Список моделей проверяет доступность
в аккаунте, но не поддержку всех нужных функций:

```sh
docker compose -f compose.yaml -f compose.real.yaml exec -T app python -m backend.app.ai.smoke --list-models
```

После выбора точного ID модели в `AI_MODEL` и повторного `up`:

```sh
docker compose -f compose.yaml -f compose.real.yaml exec -T app python -m backend.app.ai.smoke --smoke
```

В режиме готового набора заменить `compose.real.yaml` на
`compose.artifacts.yaml`. Прямой запуск `python -m backend.app.ai.smoke` вне
контейнера читает окружение процесса и сам `.env` не загружает.

Команда `--smoke` расходует API-кредиты: проверяет структурированный текст и
один полный вызов функции на искусственных данных. Всего до трёх
Responses-запросов в общем бюджете времени; реальные транзакции в эту проверку
не передаются. Успешный JSON фиксирует модель, дату и задержку. Эти значения
записываются в отчёт только после фактического выполнения; успех одного запроса
не подтверждает лимиты аккаунта или производительность на всех сценариях.

При обычной работе кнопок AI провайдер получает необходимые поля выбранной
карточки и оснований, вопрос и результаты разрешённых проверок. Полный расчёт
Parquet и обязательные CSV остаются локальными и от провайдера не зависят.

Формат API сверён с официальными руководствами
[Function calling](https://developers.openai.com/api/docs/guides/function-calling),
[Structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs)
и [Reasoning](https://developers.openai.com/api/docs/guides/reasoning).

## Состояние проверки

| Область | Подтверждение |
|---|---|
| Конфигурация, контекст, стабильные основания и fallback | Автоматические проверки на искусственном Store |
| Explain, структура и числовые основания | Автоматические проверки; работу AI с ключами подтвердил пользователь |
| Investigate, разрешённые функции, бюджет, trace и ограничения | Автоматические проверки с имитацией провайдера |
| Реальные Parquet → Store → API → граф и карточка | Проверено на предоставленном наборе; интеграция завершена |
| Локальный fallback на настоящем Store | Проверен в HTTP и браузере |
| Точная модель, задержка и полный function round trip живого API | Отдельный измеренный протокол не записывался; доступен opt-in smoke выше |

Подтверждение пользователя не заменяет измеренный протокол API, а отсутствие
такого протокола не означает, что интеграция приложения остаётся незавершённой.
