# A — Аналитика и выгрузки

**Goal:** Получить из трёх настоящих parquet все обязательные результаты с проверяемыми правилами за ≤300 секунд.

**Architecture / Tech Stack:** локальный Python-пайплайн; pandas, PyArrow, NetworkX. Сервер и AI читают его результаты.

**Spec:** [архитектура](../specs/2026-09-23-money-graph-design.md), [контракт](../../contracts/money-graph-v1.md), [общий план и ограничения](2026-09-23-money-graph-parallel.md).

**Входная зависимость:** реальные parquet и согласование математических правил тимлидом. Схема входа и численные пороги сейчас не утверждены. Имена колонок и показатели нельзя угадывать.

## Владение

Создать `backend/app/analytics/{io,audit,features,roles,clusters,priority,checks,pipeline,cli}.py`, `config/{input_mapping,rules}.json`, `tests/analytics/`, `docs/methodology.md`.

Не менять модели `backend/app/contracts.py` самостоятельно: согласовывать добавление метрик с B. Выгрузки принадлежат A.

**Produces:** `run_pipeline(input_dir: Path, output_dir: Path, rules_path: Path, mapping_path: Path) -> RunManifest`; `check_concentration(gid: str, edges: list[EdgeRecord]) -> dict`. Сигнатуры и возвращаемые поля — в контракте.

## A1. Проверенный вход и аудит — первые 40 минут

- [ ] Прочитать только схему каждого parquet, затем строки; записать реальные названия/типы колонок и необходимые преобразования в input_mapping.json.
- [ ] Выяснить, чем является строка edges: агрегатом направленной пары или отдельным событием; установить ключи transactions. Идентичные строки без уникального id не удалять автоматически: это могут быть реальные повторные переводы.
- [ ] Проверить уникальность node gid, ссылки source/target, суммы, пропуски и доступность seed/depth. Несуществующие концы рёбер и противоречивые id — явная ошибка с диагностикой, а не тихое удаление.
- [ ] Определить единицу денег, точное представление и политику самопереводов. Если есть время, проверить формат и часовой пояс; если времени нет, временные проверки не включать.
- [ ] Сверить агрегаты transactions с edges; выбрать и задокументировать один источник сумм. Сохранить расхождения в audit.json. Не складывать объёмы двух таблиц.
- [ ] Построить граф, сначала добавив все nodes, потом рёбра, чтобы сохранить изолированные узлы.
- [ ] Вывести фактические counts и сравнить с брифом. Отличия расследовать и описать; алгоритм не должен подменять результат ожидаемыми числами.
- [ ] Определить происхождение флагов наблюдаемости. Предпочесть явные признаки обхода. Восстановление глубины по seed допустимо только после проверки условий построения; если невозможно установить признак, оставить null и ограничение.

**Проверка:** искусственные gid `0007` и `7` различаются; изолированный узел остаётся; неизвестная колонка вызывает понятную ошибку; дубликат id не теряется молча.

## A2. Метрики и математическая спецификация — до 60-й минуты

- [ ] Посчитать базовые метрики контракта по всему наблюдаемому графу. Для out_in_ratio при in=0 вернуть null; не зажимать значение выше 1 до 1.
- [ ] Реализовать check_concentration: максимум исходящей суммы по получателю / общий исходящий объём. При нулевом исходящем объёме доля null. Результат сверить с ручным примером: 30 и 70 KZT двум получателям дают 0.7.
- [ ] Подготовить таблицу шести ролей: список метрик, формула AND/OR, конкретные пороги, условия применимости при неполноте, формула role_score, пример прохождения и непрохождения.
- [ ] Отдельно определить остаточный peripheral, порядок конфликтов и правило `insufficient_evidence`; сверить с контрактом. Запретить terminal на основании нулевого исходящего у обрезанного узла или при неизвестной полноте, если нет другого независимого основания.
- [ ] Предложить один алгоритм кластеризации внутри слабосвязных компонент, его вес/направленность, фиксированный seed и обработку одиночных узлов. Указать, как из метрик кластера получаются формальные гипотезы назначения.
- [ ] Предложить одну явную формулу priority_score: метрики, нормировка, веса, обработка пропусков, влияние качества данных и tie-break по gid. Score приоритета не подменяет role_score.
- [ ] Передать эту короткую спецификацию тимлиду на согласование; записать утверждённый вариант в rules.json и docs/methodology.md. Эта проверка нужна до финального применения ролей, но не блокирует остальные направления.

**Приёмка A2:** каждое число итогового score можно пересчитать; каждому условию соответствует actual, threshold, passed и rule_id. Если решения не утверждены к 60-й минуте, сообщить интегратору о зависимости, продолжить вход/метрики/контракт без выдачи черновых ролей за окончательные.

## A3. Полный проход — до 120-й минуты

- [ ] Реализовать утверждённые предикаты как обычные функции над метриками и конфигурацией. Ни gid, ни ожидаемая роль конкретного клиента не участвуют в ветвлениях.
- [ ] Рассчитать роль и status каждого узла; создать локальные объяснения из фактически сработавших условий. Для неполноты добавить конкретное ограничение.
- [ ] Выполнить кластеризацию, присвоить детерминированные ids, сформировать гипотезы назначения по правилам. Обработать singleton без искусственного присоединения к чужой компоненте.
- [ ] Рассчитать приоритеты всех узлов, отсортировать детерминированно, подготовить первые 20 без дубликатов. Мало оснований — явно слабая гипотеза, а не придуманный риск.
- [ ] Записать файлы контракта во временный каталог запуска; валидировать записи моделями B; записать manifest последним и опубликовать завершённый каталог.
- [ ] Передать B путь к настоящему набору и три настоящих примера: обычный узел, граница обхода, seed с ограничением входа. Демо-примеры выбираются из результатов.

## A4. Проверка и воспроизводимость — до 240-й минуты

- [ ] Написать небольшие синтетические проверки для утверждённых правил: граница каждого порога, конфликт двух ролей, недостаточные данные. Ожидания в тестах основаны на принятой формуле, а не на production gid.
- [ ] Проверить, что обрезанный узел с out_degree=0 не получает terminal только из-за нуля; seed с in=0 не вызывает деления на ноль и ложного утверждения о реальном источнике денег.
- [ ] Проверить уникальность назначений, полное покрытие nodes, суммы агрегатов, конечность score, принадлежность кластеров компонентам, минимум 20 строк топа на основном наборе.
- [ ] Дважды выполнить полный расчёт с одинаковыми данными и конфигурацией; сравнить содержательные поля ролей, кластеров и приоритетов, исключив время запуска.
- [ ] Замерить весь процесс до закрытия последнего обязательного файла; сообщить B общее время и время стадий, ОС, CPU и RAM. Не использовать UI-кэш в этом замере.
- [ ] Завершить docs/methodology.md: словарь метрик простым языком, все формулы, ограничения интерпретации и план масштабирования.
