# C — Интерфейс аналитика

**Goal:** Пользователь находит gid, видит наблюдаемые связи, проверяемое объяснение роли и приоритета, затем запускает один из двух AI-режимов.

**Architecture / Tech Stack:** React, TypeScript, Vite, Cytoscape.js; один экран с панелями. Все данные приходят из API B.

**Spec:** [архитектура](../specs/2026-09-23-money-graph-design.md), [контракт](../../contracts/money-graph-v1.md), [общий план и ограничения](2026-09-23-money-graph-parallel.md).

## Владение

Создать `frontend/` со своим package.json и lock-файлом. Минимальное разделение: `src/api/client.ts`, `src/types/api.ts`, `src/App.tsx`, `src/components/{SearchPanel,GraphPanel,NodeDetails,PriorityTable,ClusterList,AiPanel}.tsx`, `src/styles.css`.

**Consumes:** HTTP-контракт B, снимок contracts/openapi.json и общие тестовые ответы. **Produces:** приложение и статическая сборка `frontend/dist`, которую обслуживает B.

В состоянии экрана хранить `run_id`, выбранный gid/cluster, радиус и данные ответа. Типы согласуются с B; формулы и итоговые score frontend не рассчитывает. Вызовы провайдера AI идут через локальный backend.

## C1. Каркас и основной сценарий — до 60-й минуты

- [ ] Создать Vite-проект и один экран: слева поиск/приоритеты/кластеры, в центре граф, справа карточка и AI-действия. Настроить /api proxy на адрес B.
- [ ] Взять общий контракт и примеры B; отрисовать строковый gid, роль, оба score и состояние `insufficient_evidence`. Деньги форматировать для отображения, сохраняя точный исходный текст для карточки/подсказки.
- [ ] Добавить поиск точного gid с Enter и кнопкой. Не преобразовывать ввод в число. Неизвестный gid показывает отсутствие результата и очищает устаревшую карточку.
- [ ] Загрузить топ-20 и список кластеров. Нажатие строки выбирает соответствующий узел или кластер.
- [ ] Отрисовать граф через Cytoscape.js с направлениями рёбер, легендой ролей и выделенным выбранным узлом. Подписывать gid выбранного/наведённого узла, чтобы уменьшить шум.
- [ ] Связать клик по узлу с тем же действием выбора, что поиск. Добавить загрузку и ошибку API с кнопкой повторить.

**Проверка к 60-й минуте:** один тестовый узел через API, таблицу и граф открывает одну и ту же карточку. Тестовый источник данных обозначен; фикстуры не выданы за результаты кейса.

## C2. Настоящие данные и объяснимость — до 180-й минуты

- [ ] Переключить API на настоящий набор B. Проверить gid из артефактов A через поиск и топ.
- [ ] Показать role_explanation и evidence в виде «показатель / фактическое значение / условие / выполнено». Пояснить role_score и priority_score разными подписями.
- [ ] Показать `outbound_censored`, `inbound_incomplete`, seed и неизвестную полноту в карточке. Для неизвестных значений использовать «нет данных», а не 0.
- [ ] Добавить окружение радиуса 1/2, выбор кластера и компоненты. Компоненты для минимального интерфейса вывести группировкой списка кластеров по component_id.
- [ ] При `truncated=true` показывать «Показано X из Y узлов выбранной области». Отдельно пояснить, что карточные метрики рассчитаны на всём наблюдаемом графе.
- [ ] Ограничить работу раскладки; после завершения раскладки остановить её непрерывное выполнение. Сохранять масштаб при обновлении карточки, если состав графа не изменился.
- [ ] Подключить explain и investigate с вопросом пользователя. Показать ход ожидания, итог, основания, выполненные проверки и `fallback` без маскировки под ответ модели.
- [ ] При смене run_id очистить старые результаты AI и выбранную карточку, загрузить свежие данные. На 409 показать предложение обновить набор.
- [ ] Добавить скачивание обязательных файлов по API B.

## C3. Проверка экрана и сборка — до конца пятого часа

- [ ] Проверить поиск `0007`, неизвестного gid, узла без рёбер и обрезанного узла на общих фикстурах; затем три реальных примера A.
- [ ] Проверить быстрый выбор двух разных узлов: поздний ответ первого запроса не должен перезаписать карточку второго. Использовать отмену запроса или проверку текущего id/run_id перед применением результата.
- [ ] Проверить null/0 и диапазоны score: null показывается текстом, 0 остаётся нулём; роль не заменяется числом score.
- [ ] Проверить потерю backend и отказ AI: основной интерфейс сохраняет понятное состояние, запрос можно повторить.
- [ ] На максимальной выдаче в 300 узлов проверить отзывчивость поиска и выбор узла; при необходимости снизить UI-лимит. Это ограничение отображения, а не анализа.
- [ ] Проверить окно 1366×768: поиск, граф и карточка достижимы, длинный текст прокручивается, элементы имеют подписи и клавиатурный фокус.
- [ ] Собрать статические файлы и проверить их через FastAPI B. Зависимости графа включаются в сборку, чтобы основной экран работал без внешних CDN.
- [ ] Передать B команды запуска/сборки и один скриншот; помочь выбрать короткий сценарий демо.

**Планируемые команды после реализации (в frontend):**

```bash
npm ci
npm run dev
npm run build
```

Для проверки гонки ответов и run_id достаточно одного целевого теста состояния выбора; для расположения и графа провести браузерный сценарий. Не тратить время на снимки каждого декоративного элемента.

**Готово, когда:** поиск, выбор из топа и клик по графу синхронно открывают настоящую карточку; ограничения видны; выгрузки доступны; оба AI-режима или их честно обозначенный fallback отображаются.

**Стартовый запрос:** «Прочитай план C, архитектуру и контракт. Работай только во frontend. Используй общие ответы B, не создавай собственные поля и аналитические формулы. Сначала собери поиск → граф → карточка, затем AI-панель. Изменения контракта согласуй с B».

Документация событий и раскладок: [Cytoscape.js](https://js.cytoscape.org/).
