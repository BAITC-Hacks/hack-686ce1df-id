# D — AI-пояснитель и AI-исследователь

**Goal:** Два ограниченных режима помощи аналитику с проверяемыми основаниями и работающим локальным fallback.

**Architecture / Tech Stack:** Python-модуль в том же процессе FastAPI; API одного выбранного провайдера; подготовленные функции ResultStore. Обязательные результаты аналитики от внешнего API не зависят.

**Spec:** [архитектура](../specs/2026-09-23-money-graph-design.md), [контракт](../../contracts/money-graph-v1.md), [общий план и ограничения](2026-09-23-money-graph-parallel.md).

## Владение и интерфейсы

Создать `backend/app/ai/{provider,service,tools,prompts,validation}.py`, `tests/ai/`, `docs/ai.md`. Зависимости и .env.example обновляет B по запросу D.

**Consumes:** модели ExplainRequest, InvestigateRequest, AIResponse от B; текущий ResultStore и функции A через него.

**Produces:**

```python
async def explain(request: ExplainRequest, store: ResultStore) -> AIResponse: ...
async def investigate(request: InvestigateRequest, store: ResultStore) -> AIResponse: ...
```

Все публичные ответы соответствуют AIResponse из контракта. Для тестов provider заменяется имитацией, которая возвращает заданные ответы/вызовы. Основные тесты не тратят API-кредиты.

## D1. Провайдер, контекст и fallback — до 60-й минуты

- [ ] Проверить доступные в аккаунтах модели, поддержку нужных структурированных ответов/вызовов функций и ограничения; выбрать один работающий вариант. Название модели задаётся конфигурацией, а не разбросано по коду. Не предполагать взаимозаменяемость OpenAI и NVIDIA API.
- [ ] С B согласовать серверные переменные `AI_PROVIDER`, `AI_MODEL`, ключ выбранного провайдера, `AI_TIMEOUT_SECONDS=30`, `AI_MAX_TOOL_CALLS=3`. В docs/ai.md записать фактические проверенные значения и ограничения.
- [ ] Сформировать контекст из выбранного NodeRecord/ClusterRecord, локальных объяснений, ограничений выборки и run_id. Передавать только нужные для вопроса наблюдаемые данные.
- [ ] Назначить основаниям стабильные идентификаторы в рамках запроса и передать модели их список. Сохранить карту evidence_id → реальный объект, чтобы проверить ссылки ответа.
- [ ] Реализовать локальную справку из role_explanation / priority_explanation / cluster.hypothesis и quality. Она возвращается при отсутствии ключа или недоступности API с `status="fallback"`.
- [ ] Через тестового провайдера вернуть валидный AIResponse. Передать B/C пример успешного ответа и fallback.

## D2. Режим «Объяснить» — до 120-й минуты

- [ ] Сделать один внешний запрос с ограниченным контекстом и структурой ответа AIResponse без цикла функций. Проверить поддерживаемую схему выбранного провайдера.
- [ ] В инструкции задать: использовать только переданные основания; говорить о наблюдаемой сети и гипотезах; отличать отсутствие данных от нуля; описывать ограничения обхода; не изменять итоговую роль/score.
- [ ] Проверять ссылки evidence_ids, структуру и воспроизводимые числовые утверждения. Не считать соответствие JSON-схеме доказательством достоверности свободного текста.
- [ ] Невалидный ответ, отказ провайдера или превышение срока превращать в явный fallback. Не выдавать частичный ответ за завершённую проверку.
- [ ] Проверить explain на реальном узле A с ограничением наблюдаемости; карточка и основания ответа должны относиться к одному run_id.

## D3. Режим «Исследовать» — до 180-й минуты

- [ ] Реализовать белый список из `get_node`, `get_neighbors`, `get_cluster`, `check_concentration`. Аргументы и возвращаемые формы — из контракта. Первые три берутся из B; последняя использует формулу A через Store.
- [ ] Проверять имя, схему аргументов, существование id и совпадение run_id до исполнения. Запрошенная неизвестная функция не выполняется.
- [ ] Реализовать цикл: модель выбирает функцию → сервер выполняет → результат получает evidence_id → модель формирует гипотезу или выбирает следующую проверку.
- [ ] Ограничить суммарно тремя исполнениями функций и 30 секундами весь пользовательский запрос. Несколько функций в одном ответе модели считаются по отдельности; оставшиеся сверх лимита не выполняются.
- [ ] Сохранить trace: имя, аргументы, результат и основание каждой выполненной проверки. Показывать trace в итоговом AIResponse, без внутренних рассуждений модели.
- [ ] При исчерпании бюджета завершить ответ доступными результатами с явным ограничением либо локальным fallback; уже выполненные проверки сохранить.
- [ ] Обработать вопросы вне доступных данных текстом о границах наблюдения. Внешнее обогащение и изменение конфигурации правил не являются функциями помощника.

Механизм взаимодействия модели и подготовленных функций: [официальная документация OpenAI](https://developers.openai.com/api/docs/guides/function-calling). Для NVIDIA проверить документацию конкретного выбранного endpoint до подключения.

## D4. Целевые проверки — до 240-й минуты

Создать тестового провайдера со сценариями ниже; для каждого сценария проверить AIResponse и число реально исполненных функций.

| Сценарий | Ожидаемое поведение |
|---|---|
| Ключ отсутствует | fallback, 0 внешних запросов, локальные основания доступны |
| Провайдер завис или ответил ошибкой | возврат в пределах общего тайм-аута, status=fallback |
| Модель запросила неизвестную функцию | 0 исполнений этой функции; диагностируемый ответ |
| Модель запросила четыре функции одним пакетом | исполняется не больше трёх; лимит отражён |
| Модель сослалась на несуществующее evidence_id | ответ отклонён, локальный fallback |
| Подмена gid или несовместимый run_id | запрос не смешивает данные запусков; HTTP-слой B возвращает нужную ошибку |
| Узел на границе обхода без исходящих | итог не заявляет установленный реальный terminal; ограничение сохранено |
| Один поток 30 KZT, второй 70 KZT | check_concentration возвращает 0.7; числовое основание соответствует вычислению |

- [ ] После тестов сделать минимальный контрольный запрос к выбранному провайдеру на разрешённых данных и зафиксировать задержку/ошибки. Не обещать лимит запросов по одному только размеру выданных кредитов.
- [ ] Вместе с C проверить пользовательский вопрос по реальному узлу: выполненная функция и её числа видны в панели.
- [ ] Передать B docs/ai.md: конфигурация, режимы, функции, ограничение бюджета времени, fallback, известные ограничения достоверности. Зафиксировать фактически выбранную модель.

**Планируемая команда после реализации:** `python -m pytest tests/ai -q`.

**Готово, когда:** оба режима работают на том же Store, что интерфейс; основания отображаются; API-сбой не ломает основной продукт; роли и score не меняются из ответа LLM.

**Стартовый запрос:** «Прочитай план D, архитектуру и контракт. Работай только в AI-модуле. Сначала реализуй explain и локальный fallback с тестовым провайдером; затем ограниченный investigate. Используй функции B/A, не переписывай расчётные формулы. Общие зависимости и API-модели согласуй с B».
