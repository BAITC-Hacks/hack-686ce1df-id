# Граф денег: согласованная архитектура

Статус: архитектура согласована в разговоре 23 сентября 2026 года. Этот документ фиксирует её для команды. Контракт v1 и распределение работ предложены в сопутствующих планах. Численные правила ролей, кластеризации и приоритизации ещё не согласованы; их утверждение — отдельная задача аналитического направления.

## Результат

Локальное веб-приложение для исследования наблюдаемой транзакционной сети. Для каждого исходного узла: одна основная роль из `consolidator / transit / distributor / terminal / coordinator / peripheral`, формальное объяснение и score. Для сети: кластеры с гипотезами назначения, топ не менее 20 узлов с основаниями, граф с поиском по `gid`.

Полный пересчёт от исходных parquet до всех обязательных выгрузок — не более 300 секунд локально, без использования готовых результатов предыдущего запуска. Скорость пока не измерена.

## Исходные сведения

По брифу: nodes 2248, edges 3119, transactions 4840; 81 seed, обход на четыре колена только по исходящим внутрибанковским переводам за июль 2026 с порогом 5000 KZT. 444 узла на границе обхода, 31 seed без исходящих, 16 слабосвязных компонент.

Эти числа — ожидаемые характеристики данного набора для проверки, а не константы алгоритма. В репозитории при составлении документов есть только исходный README; схемы и содержимое parquet не проверены.

## Четыре части системы

1. **Аналитическое ядро:** Python, pandas, PyArrow, NetworkX. Проверка входа, метрики, правила ролей, кластеризация, приоритизация, обязательные текстовые объяснения по шаблонам. Обработка всех исходных узлов, включая изолированные.
2. **Артефакты запуска:** локальные Parquet и JSON/CSV. Результаты, аудит данных, параметры правил, версии зависимостей, контрольные суммы входа и измеренное время. Артефактами владеет направление аналитики.
3. **Один Python-сервер:** FastAPI. Читает законченный набор результатов, предоставляет API интерфейсу и выполняет подготовленные функции для AI. Ключи провайдеров находятся на сервере.
4. **Интерфейс:** React, TypeScript, Vite, Cytoscape.js. Поиск и списки слева, граф в центре, карточка с объяснениями и AI справа. Граф показывает выбранную компоненту, кластер или ограниченное окружение узла.

Аналитический код запускается отдельной командой и переиспользуется сервером для дополнительных проверок. Основные роли не пересчитываются при каждом изменении фильтра в интерфейсе. Для MVP результаты хранятся в файлах и памяти одного процесса сервера.

## AI

- Режим «Объяснить»: справка по рассчитанным данным выбранного узла или кластера.
- Режим «Исследовать»: до трёх выполнений функций из фиксированного набора за один вопрос. Функции читают данные и возвращают вычисленные основания.
- Утверждённые роли, score и конфигурация правил остаются результатом формального расчёта. AI формирует дополнительные объяснения и гипотезы, которые отображаются с основаниями и ограничениями.
- Обязательные объяснения и гипотезы кластеров создаёт локальное ядро. Недоступность AI не блокирует обязательные выгрузки и демо основного сценария.
- На первом запуске подключается один провайдер. Доступны заявленные кредиты $150 OpenAI и $150 NVIDIA; конкретные модели, лимиты и условия этих аккаунтов ещё не проверены. Автоматическое переключение между провайдерами вне минимального объёма.

## Качество и объяснимость

- Для каждой роли требуется проверяемый предикат с порогами и определённое разрешение конфликтов между ролями. Выбор чисел не делегируется LLM во время расчёта.
- Score соответствия роли и score приоритета — разные значения; ни один не интерпретируется как вероятность виновности.
- Отсутствующее значение отличается от нулевого. Неизвестная полнота наблюдения не считается доказанной полнотой.
- Нулевые исходящие при обрезанном обходе недостаточны для terminal. Даже terminal вне границы обхода означает гипотезу в пределах данного окна и фильтров, а не доказанный конечный получатель средств.
- Неполные входящие seed учитываются при применении правил и отношений сумм. Суммы переводов не являются остатком на счёте.
- Внешние персональные и другие атрибуты не добавляются. Все формулировки о назначении и ролях — гипотезы.
- Данные, карточки и AI-основания связаны одним `run_id`. Не допускается смесь результатов разных запусков.

## Приёмка

1. На всех исходных узлах есть роль, score, машинно проверяемое основание и текстовое объяснение; для недостаточных данных явно указан статус.
2. Есть принадлежность кластеру и воспроизводимая гипотеза его назначения; одиночные узлы сохранены.
3. Топ содержит минимум 20 различных узлов, если во входе их не менее 20; каждый имеет основание приоритета.
4. Поиск точного `gid` открывает граф и карточку одного узла. Неизвестный `gid` даёт понятное отсутствие результата.
5. Полный запуск от трёх parquet до закрытия всех обязательных файлов измерен и укладывается в 300 секунд на описанном ноутбуке.
6. При отключённом AI обязательный сценарий и выгрузки работают.
7. README содержит запуск, правила и пороги, ограничение наблюдения, измерение времени, масштабирование до порядка 1 млн узлов.
